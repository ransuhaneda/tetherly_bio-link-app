# Use recoverable account deletion before permanent purge

Account deletion immediately unpublishes the creator and places the entire account in a 30-day pending-deletion state instead of deleting only its one-to-one profile. The creator enters their current password directly in a focused, repository-deletion-style modal that lists every consequence; failed confirmation is limited to five attempts per minute per account and IP, with the API-provided wait shown as a countdown in the modal. Tetherly signs them out, reserves their username, and sends an immediate deletion-request confirmation containing the request and purge dates, username, public-visibility state, authenticated restoration path, and security guidance. Successful authentication during the recovery window opens an explicit restoration screen rather than restoring automatically; restoration returns an unpublished draft. The MVP shows the calendar purge date without a live days-remaining counter. The recovery deadline is authoritative: restoration is unavailable after that timestamp even if physical deletion is still pending. An indexed, bounded purge runs once daily during an off-peak window, retries failed external-file cleanup while the account remains inaccessible, and releases the username only after required cleanup succeeds. The product copy presents the calendar date as the deletion date despite the purge potentially completing during the following daily run. This preserves the invariant that every active account owns a profile while protecting against accidental deletion.
